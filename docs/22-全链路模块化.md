## 一、先回答最尖锐的问题：组装难度高不高、复用率高不高

### 1.1 组装难度：中等偏高，而且不是线性的

核心机制：**每叠一层图生图，身份保真度就下降一档。**

预估合格率（待首批实测校正，我会把它做成表）：

| 叠加层数 | 估计出图/可用比 | 说明 |
|---|---|---|
| 1 层（基底） | ≈1 : 1 | 基本稳 |
| 2 层（基底+服饰） | ≈2 : 1 | 可接受 |
| 3 层（+发型或状态） | ≈3 : 1 | 需要挑 |
| 4 层以上 | 不建议 | 脸会明显漂 |

> **这张表是估计值，不是实测值。** 第一批资产跑完我会用真实数据替换它。
> 在拿到真实数字之前，任何"复用率提升了多少倍"的说法都是吹牛。

### 1.2 复用率高不高：要分三种"复用"，别混着说

| 复用类型 | 高不高 | 说明 |
|---|---|---|
| **真复用**（同一文件被多个镜头直接引用） | **低** | 每个镜头仍要单独生成图和视频，不可能"一图多用" |
| **参数复用**（同一套资产，换参数生成新图） | **高** | 这是主要收益 |
| **零成本复用**（成片镜头靠剪辑手段重上） | **中** | 镜像 / 变速 / 裁切 / 换上下文，×3~5 |

### 1.3 所以模块化真正省下的是什么（这句最重要）

> **模块化不减少"生成的次数"，它减少"决策的次数"和"试错的次数"。**

一个镜头的工作流从：
```
想 → 写 prompt → 生成 3 次 → 挑一张 → 视频生成 2 次 → 挑一版
```
变成：
```
选 beat 配方 → 选 EXP/POSE → 生成 1 次 → 确认 → 视频 1 次
```

**省的是时间和配额，不是资产数量。**
纸面上"4320 种造型"是数字游戏，真实收益是一镜从 5 次调用降到 2 次——**效率提升 60%**。

### 1.4 但模块化有一个别人给不了的杀手价值

**可替换性。** 某一镜不满意，只需换**一个维度**重出，不用推翻整条。
以前是"这镜不对 → 重写 prompt → 全变"；现在是"这镜表情不对 → 只换 EXP-03"。

## 二、场景模块怎么拆

**按"摄影机可以走动的空间"拆，不按"地点名"拆。** 一个 SET = 一个能 360° 布机的物理空间。

### 2.1 四类资产

| 资产 | 内容 | 数量 |
|---|---|---|
| `SET-<名>-map` | **轴线平面图**（俯视：人物位、机位、屏幕方向、光源位） | 1 |
| `SET-<名>-wide` | 全景（建立镜头用） | 1 |
| `SET-<名>-mid` | 中景（人物在其中） | 1–2 |
| `SET-<名>-detail` | 细节（石阶、门框、水面、灯笼） | 2–3 |

### 2.2 三个正交变量（复用的核心）

```
SET（空间）× LAYER（景深层）× TIME（光照时间）= 镜头数
```

**`LAYER` 景深层——这是"沉浸感"的工程来源：**

| LAYER | 作用 |
|---|---|
| `LAYER-reeds` | 前景芦苇（压住画面一角，制造"我在草丛里"） |
| `LAYER-lantern` | 灯笼（暖光锚点，用亮度调制雨的可见性） |
| `LAYER-eave` | 屋檐/门框（框住画面，制造窥视感） |
| `LAYER-water` | 前景水面（反光层） |

**同一个人物镜头，前面加一层芦苇，观感完全不同。**
这是最便宜、效果最直接的一层，比重新生成场景便宜得多。

**`TIME` 光照状态：**

| TIME | 用在哪 |
|---|---|
| `rain_night` | 主基调 |
| `lightning` | 闪电瞬间（一个 SET 只生成一次，靠调色+亮度脉冲模拟） |
| `fire` | 灶火（室内暖光） |
| `dawn` | 雨停/黎明（结尾用） |

### 2.3 一个 SET 能撑多少镜头

```
1 张 map + 1 wide + 2 mid + 3 detail = 7 张
× 2 个 TIME（调色/亮度脉冲实现，不需要重新生成）
× 3 个 LAYER（叠加，不需要重新生成）
→ 可支撑 8~12 个镜头
```

### 2.4 硬要求：轴线图必须有

`SET-<名>-map` 不是"参考图"，是**纪律文件**。上面必须标：
- 人物固定位置（左/右，离水多远）
- 蛟出现的方向
- 所有机位允许落在哪一侧
- 主光源方向

**没有这张图，跨镜头的空间一定乱。** 我在前面几版踩过这个坑（"蛟朝镜头冲来"和"她望向镜头后方"互相打架）。

## 三、音频字幕怎么拆

### 3.1 音频：六层，各管一件事

| 层 | 前缀 | 内容 | 复用方式 |
|---|---|---|---|
| 环境 | `AMB` | 雨 / 水 / 风 / 室内安静 | 做 4–5 条，全片铺，交叉淡化 |
| 事件 | `EVT` | 水花 / 脚步 / 木头 / 门轴 / 石落 | 建 20 条音效库，反复用 |
| 人声 | `VOX` | 对白 / 呼吸 / 喘 / 哭 | 每句独有，但**语速停顿是配方** |
| 生物 | `CRE` | 龙吟 / 低吼 / 水下闷响 | **合成器参数化**（体型/距离/情绪） |
| 音乐 | `MUS` | 有则用，无则空 | 可跨集 |
| 设计 | `DES` | 低频冲击 / 静默 / 耳鸣 | 模板化，位置可复用 |

**关键纪律（已经踩过）：**
- **AMB 必须一条连续铺满全片**，否则每切一次换一个空间
- 各镜事件音按绝对时间铺开，**首尾 0.35s 淡入淡出互相压住** → 画面硬切，声音重叠

**`CRE` 参数化怎么做：**
`synth_roar.py` 已经是参数化的雏形（基频轨迹、粗糙度、混响）。扩成参数表：

| 参数 | 效果 |
|---|---|
| `body_size` | 基频越低 = 体型越大（39Hz 巨物 / 90Hz 小蛟） |
| `distance` | 混响越长、高频越少 = 越远 |
| `emotion` | 粗糙度与起伏 = 威胁/痛苦/呼唤 |

一次做好，全剧所有生物音都从这套参数出，不用每次生成。

### 3.2 字幕：不是资产，是**规则 + 由声音驱动的数据**

| 要素 | 处理 |
|---|---|
| 样式 | **一次定死**：字体、字号、描边、底部安全区、淡入淡出 |
| 类型 | 对白（居中下）/ 旁白（左上）/ 拟音说明（右下小字） |
| 时间轴 | **由 VOX 层自动检测驱动**（已实现：能量阈值 + 0.3s 空隙容错） |
| 内容 | 存在剧本里，不重复做 |

**复用点：** 字幕条目不跨集复用，但**样式规范与自动对齐流程**一旦建好，全剧零成本。
一条 40 秒片能省 20 分钟对时间轴。

## 四、情节怎么拆（最需要小心的地方）

**故事不能被模块化到失去意义。但结构可以。**

### 4.1 三层

```
PREMISE 前提（一句话）
  └─ BEAT 节拍（6–10 个，每个有固定"功能"）
       └─ SHOT RECIPE 镜头配方（每个 beat 类型对应一套固定镜头序列）
```

### 4.2 `PREMISE` 一句话公式

> **谁** + **想要什么** + **被什么拦住** + **代价是什么**

《走蛟》：渔家女阿月 + 想给爹收尸/想明白爹怎么死的 + 被一条渡劫的蛟拦住 + 代价是她必须选择说"蛇"（报仇）还是"龙"（放过）。

### 4.3 `BEAT` 可复用清单（跨集通用）

| BEAT | 功能 | 观众心理 |
|---|---|---|
| `OMEN` | 征兆（血、水动、鸟飞） | 出什么事了？ |
| `NOTICE` | 有人察觉 | 他看见了什么？ |
| `MISREAD` | 误判（以为是别的） | 我也被骗了 |
| `CONFIRM` | 看清了 | 原来这么大 |
| `REACT` | 反应（逃/僵/叫/护） | 我会怎样 |
| `COST` | 代价（有人受伤/失去） | 这不公平 |
| `CHOICE` | 抉择 | 他会怎么选 |
| `AFTERMATH` | 余波 | 然后呢 |

**这八个 beat 是全剧通用骨架**，换成"火"、"洪水"、"瘟疫"都成立。
**这才是真正的复用层级——复用的是结构，不是画面。**

### 4.4 `SHOT RECIPE` 镜头配方（效率的核心）

每个 beat 类型，对应一套**已经打磨过**的镜头序列：

| BEAT | 配方 | 总时长 |
|---|---|---|
| `OMEN` | 环境推轨（4.6s）→ 细节特写（1.5s） | 6.1s |
| `NOTICE` | 中景人物（2.5s）→ 视线方向空镜（2.0s） | 4.5s |
| `CONFIRM` | 远景（3s）→ 中景（2s）→ 近景细节（1.5s） | 6.5s |
| `REACT` | 脸部近景（1.8s）→ 手/脚（1.2s）→ 后退半步（1.5s） | 4.5s |
| `COST` | 冲击（1.0s）→ 反应（1.5s）→ 静（2.0s） | 4.5s |
| `CHOICE` | 脸（2.5s）→ 对象（2.0s）→ 脸（2.5s） | 7.0s |

**这是"镜头往高质量方向走"的真正机制：**
配方是**打磨过一次**的，每次复用都是那个质量；
而不是每次临场发挥、每集重新想分镜。

> 一集 = 选 6–10 个 beat → 套对应配方 → 填 EXP/POSE/场景 → 出片。
> 分镜工作从"创作"变成"装配 + 微调"。

## 五、还缺的大模块（你没提但必须补）

| 模块 | 作用 | 为什么必须 |
|---|---|---|
| `EDIT` 剪辑模板 | 节奏配方（建立 4.6 / 反应 1.8 / 冲击 1.5） | 节奏是资产，不是灵感 |
| `SHOT RECIPE` 镜头配方 | beat → 镜头序列 | 效率的核心杠杆 |
| `AXIS MAP` 轴线图 | 场景空间纪律 | 根治跨镜头空间混乱 |
| `LOOK` 造型定妆 | 组合的产物，后续锚点 | 否则每镜都在漂 |
| `QA` 质量门禁 | 每批资产的验收清单 | 没有门禁就没有标准 |
| `META` 元数据 | 命名 + 标签 + 来源 | 资产过百就找不回来 |
| `BUDGET` 配额表 | 每集预算 | 防止一天烧完全月 |

## 六、效率与质量：三个杠杆、两条纪律

### 效率三杠杆

| 杠杆 | 做法 | 收益 |
|---|---|---|
| **减少决策** | beat → recipe 配方化 | 分镜时间降 70% |
| **减少试错** | 首帧人工确认制，不通过不许调视频 | 视频调用从 3 次降到 1.3 次 |
| **减少重做** | 模块可替换，只换一个维度 | 返工范围从"整镜"缩到"一层" |

### 质量两纪律

1. **一次只改一个变量。** 同一场戏内，**角色造型锁定**，只变机位与表演。
   同时改服饰+发型+姿态+运镜，出来一定崩。
2. **配方打磨一次，复用多次。** 不要每镜重新发明调度。

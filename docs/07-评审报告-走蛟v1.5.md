## 三、发现清单（P0 = 不修不能交，P1 = 严重，P2 = 方向）

### P0 · 阻断级

**P0-1 成片 yuv444p，平台不可用**
- 锚点：`scripts/make_film_v15.py` L206–207。烧录字幕一步的 ffmpeg 命令**没有指定 `-pix_fmt yuv420p`**，ass 滤镜输出 RGB，libx264 自选 4:4:4。
- 讽刺的是 L77 的调色步骤写对了（`format=yuv420p`），最后一步丢了。
- 修法：L207 `"-crf", "17",` 后插入 `"-pix_fmt", "yuv420p",`。重跑脚本即可，零配额成本。

**P0-2 缺 AI 生成内容标识（合规硬要求）**
- 依据：2026 年起广电对微短剧实行"先备案后上线"，**每集片头 3 秒内必须有静态文字"AI 创作"或"AI 辅助制作"，字号 ≥ 画面高度 8%**；备案需提交版权链路文件与 AI 生成日志。
- 现状：片头只有"走蛟 / 民间志异"。**上传即拒**。
- 修法：ASS 片头事件加一行标识字幕（704×0.08 ≈ 56px 以上）；同时 `work/**/urls.json`、`video_urls.json` 就是现成的生成日志，整理成备案附件。

**P0-3 前 3.5 秒纯黑静音片头 = 自杀式开场**
- 实测：0–3.2s 音频 RMS 近零、画面纯黑。红果标准：0–3s 冲突锚定是生死线，完播率 <30% 即判开头失败。
- 现有片名 3.5s + 旁白铺垫约 20s 才到第一个冲突（蛟影），结构上**双重违背**前 3 秒法则。
- 修法（不换剧本前提下的最小改动）：砍掉黑场片头，冷开场直接用 shot_06（蛟眼特写）打头 1.5s → 切斗笠，片名叠加在画面上。这是纯剪辑层改动，不花配额。

**P0-4 镜 10 高潮台词音量过轻**
- 实测：镜10 语音段峰值 RMS 0.0763，镜8 为 0.3768（1/5）。
- 修法二选一：① 重生成镜10，prompt 强调"人物提高音量、声音清晰有力"；② 后期对镜10 音频段做响度归一（loudnorm / 限幅增益），零配额成本，**建议先做 ②**。

**P0-5 镜 12 结尾三重失守**
- 实测：角色形象断裂（辫子+浅衣≠黑披发+深毛衣）＋ 饱和度 22.7%（规范 30–40）＋ 82.9–90.4s 近静默。
- 修法：镜12 以 cast_ayu 为参考重生成（图像配额充裕）；饱和度纳入调色闭环（见 P1-1）；结尾加水声/鸟鸣环境层（ffmpeg 混音，零配额）。

### P1 · 严重（工艺层）

**P1-1 调色"闭环"是开环的（根因级）**
- 锚点：`make_film_v15.py` `grade_and_norm()`：
  - L52 `for it in range(2)` —— 最多 2 轮；
  - L88 收敛判据 `abs(dY)<=8 and abs(dRB)<=8` —— **饱和度从不参与判定**；
  - `sat_mul` 仅在首轮计算一次，之后不再校验。
- 实测后果：10/12 镜超界，其中 8 镜是饱和度超标。
- 修法：把 SAT 加入收敛判据与迭代变量，迭代上限提到 4；收敛后复测不达标即报错（fail loudly），不许静默输出。

**P1-2 角色规格锁定形同虚设**
- REGISTRY 锁定"粗麻短褐"，实际全片角色穿**现代高领针织毛衣**（cast_ayu/shot_02/shot_10 一致地错）。
- cast_ayu 定妆图**闭眼**——闭眼参考图丢失眼部特征，是脸漂移的隐患之一。
- 修法：重做三视图 v1.1 时**必须睁眼正视镜头**；服装在 prompt 用"粗麻质感、补丁、磨损"正向描述而非只写名词；定妆图逐项对照规格清单验收。

**P1-3 蛟资产：shot_05 报废，shot_06 扶正**
- shot_05 就是鳄鱼，不可用。REGISTRY 里"可用但偏真实鳄鱼"的措辞要改成"报废"。
- 修法照 REGISTRY v1.1 计划执行（以眼为锚反推头部 + 排除法），但补充一条：**生成后先用探针目验"有无外露獠牙/长吻"，不过就重抽**，别让鳄鱼再进成片。

**P1-4 构图同质化**
- cast_ayu / shot_02 / shot_08 / shot_10 四张全是"正面近景 + 水乡 + 船"。P0-3 的冷开场方案顺带缓解。v2 分镜表须落实报告已承诺的轴线/视线/进出画方向标注。

### P2 · 方向性（需用户拍板，执行窗口不得擅自开工）

**P2-1 横屏 × 红果是逆水行舟（对报告问题 2 的回答）**
外部核实：红果主流竖屏 1–3 分钟，单集 180s 最优；**横屏主阵地在腾讯视频 / 爱奇艺 / B 站 / YouTube**。不存在"横屏打红果"的成熟路径。
- 选项 A：保红果 → 转竖屏 9:16，构图全部重做（成本高，但资产可图生图迁移一部分）
- 选项 B：保横屏 → 换目标平台（B 站国风区与"余味"气质契合度反而最高）
- 选项 C：本片按横屏做完 v2 当**能力验证**，不追红果数据；第二集再决策
- **评审推荐 C**：已投入的资产不浪费，方向决策推迟一集，用真实数据说话。

**P2-2 余味路线 vs 强爽路线（对报告问题 1 的回答）**
90 秒容量撑不起留白叙事——留白需要观众愿意等，平台 3 秒就淘汰你。但直接废弃可惜。
- 同意执行窗口预案：**本集收尾做完（练工艺），下一集上强冲突版打平台**。备选方案（"蛇"→血雨→龙须反转）成立，且反转钩子符合"结尾 5 秒钩子"的平台公式。

**P2-3 时长（对报告问题 3 的回答）**
90s 偏短但不是当前主要矛盾。建议 v2 一集按 **120–180s** 设计（对齐红果最优区间），在视频配额（500s/天）内可容纳，废片预算另计。

**P2-4 画幅（对报告问题 4 的回答）**
704 是模型硬上限，接受。但发布版必须处理：`scale` 进 1280×720 画布上下各补 8px 黑边（或直接 crop 成 1.778），消除 20:11 非标画幅。一行 ffmpeg 参数的事。

**P2-5 对白清晰度（对报告问题 5 的回答）**
不用在"氛围 vs 清晰"二选一里硬选。正确分层：**环境音由音频层负责（雨声素材库混音），人声由生成/后期负责（响度归一）**。v1.5 为了人声压雨声是两层职责混在一起的结果。参考素材：爱给网/Freesound 雨声 + ffmpeg amix。

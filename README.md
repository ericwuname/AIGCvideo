## 二、技术栈（全部实测打通）

| 环节 | 方案 | 备注 |
|---|---|---|
| 剧本 / 分镜文本 | `agnes-3.0-flash` | OpenAI 兼容接口 |
| 图像生成 | `agnes-image-2.5-flash` | 4000 张/天，配额充裕 |
| 视频生成 | `agnes-video-2.5-flash` | **500 秒/天，是全链路瓶颈** |
| 本地图像工作台 | ComfyUI + SDXL | 已装于本地，用于角色一致性补强（IP-Adapter / LoRA / ControlNet） |
| 剪辑 | ffmpeg | 硬切、调色、混音 |
| 字幕 | ASS 字幕烧录 | ⚠️ Windows 中文路径下不要用 `drawtext`，会崩 |

**资源观**：视频配额稀缺，图像配额富余。
→ 因此核心工艺原则是：**不确定性全部前置到图像阶段**（每镜出 3 张候选挑1 张），
视频只用来做"已经确定的东西的运动"。

接口细节见 `docs/agnes-api-实测手册.md`（含全部坑位：鉴权、端点差异、字段位置、轮询）。

## 三、六条核心方法（从踩坑里长出来的）

### 1. 影视是连续的，不能按"单张好看"做
12 个镜头必须**先做空间/轴线/视线规划，再生成**。否则观众看到的是"一组插画"，不是"一场戏"。
单镜合格 ≠ 连起来能看懂—— 这是剪辑语法问题，不是画面问题。

### 2. 先建资产库，再组装镜头
资产是唯一真源，镜头只引用。编号 `AST-<类型>-<序号>-<视图>_v<主>.<次>`。
默认升小版本做局部修，不推翻全部。

### 3. 一致性靠"减少独立生成次数"来换
视频模型的 `keyframe` 模式只定首帧、不定身份——用首帧生成，人脸会换成另一个人。
必须用 `mode=reference` + 多张参考图，但 reference 也只能做到"像同一类"，做不到"同一只"。
→ 现实解法：**长镜多切、少露正脸、必要时用侧背/剪影/局部**。
终极解法是训角色 LoRA（ComfyUI + kohya_ss）。

### 4. 调色保对比，不保均值
为"手机能看清"把每镜均值强行拉到同一亮度 → 全片一片中灰 → 审美下降、压迫感消失。
**判断标准从"均值"改成 p5 / p95 / 动态范围**（目标：均值 29~35，p5=0~15，p95=80~146，动态范围 64~145）。
但交付前**必须量**：曾出现过 Y=3~16（手机黑屏）的事故。

### 5. 画面不干净才 immersive
三条：机位站进人的位置（贴水面一掌高）、前景遮挡（芦苇/雨丝压在画面前）、画面不干净（水渍/水花糊镜头/手持抖动）。

### 6. 声音割裂的解法：画面硬切，声音重叠
每镜环境音独立生成 + 硬切 → 每切一次换一个空间。
解法三层：**连续雨声底**（铺满全片）+ **事件层**（按绝对时间错开铺、首尾淡入淡出互相压住）+ **强调层**（J-cut 低频、冲击重击）。
验收指标：**切点前后响度落差 ≤1.5dB**（刻意冲击点才做大落差）。

> 完整清单见 `docs/19-镜头叙事逻辑-诊断与规范.md`，每片交付前必过 9 条。

## 五、当前痛点（希望外部 AI 重点看这里）

1. **角色一致性**是最大瓶颈。`reference` 模式做不到"同一只"，同一镜内部角形都会变。
   → 想请教：业界怎么在**不训练 LoRA**的前提下把跨镜人脸一致性做到可用？还是说 LoRA 是唯一解？
2. **动辄40% 的视频配额被浪费在试错上。** 视频 500 秒/天，图像 4000 张/天。
   → 想请教：有没有办法用图像侧的产物**预测**视频侧的成败，从而在提交前就筛掉会崩的镜头？
3. **"像东方龙"和"像真实生物"在模型里是互斥的。** 说写实→滑向鳄鱼，说东方龙→滑向插画。
   → 想请教：有没有比 prompt 工程更结构化的方法（比如给模型一个更强的概念锚，或者用 3D 代理先定形）？
